# Изменения

Все заметные изменения Synex. Версии по [Semantic Versioning](https://semver.org/lang/ru/):
выпуски `0.x` — предварительные на пути к `1.0.0`. Версия хранится в файле `VERSION`;
[workflow выпуска](.github/workflows/release.yml) публикует тег `vX.Y.Z` со сборками для
Windows, Linux и macOS.

[English version](CHANGELOG.md)

## [0.4.0] — готовится к выпуску

- Files показывает текущий каталог по одному запросу. Backend проверяет тип целей SFTP-ссылок пакетной командой, без листинга каждой цели.
- Обновлены подключение SSH, выбор сессии и терминал.
- macOS-бандл подписывается ad-hoc. CI проверяет подпись, архитектуру и запуск бинарника до упаковки и после распаковки ZIP.
- Замеры памяти сохраняют RSS независимо от доступности USS. Отчёт отмечает недоступные метрики и неполный замер.
- Лицензия MIT вложена в дистрибутивы и публикуется вместе с пре-релизом.

## [0.3.0] - 2026-11-24

- Rust-воркер обращается к Docker Engine через SSH. Backend отдаёт контейнеры, образы, статистику и логи по действующему API.
- Backend выбирает воркер для Windows x64, Linux x64, macOS Intel и Apple Silicon. Воркеры поддерживают отмену SSH-команд и SFTP-передач.
- Dashboard, Servers и Logs показывают имя пользователя выбранной SSH-сессии. Обновлены оформление страниц и терминал.

## [0.2.0] - 2026-11-24

- Добавлены IPC-клиент хоста внешних плагинов, установка и обновление локальных пакетов, разрешения и вызов действий через REST и WebSocket.
- Обновлены навигация, экраны и SSH-терминал. Упакованный UI использует порт открытого приложения. Релизные сборки проверяют HTTP и WebSocket на двух портах.

## [0.1.0] - 2026-11-20

Первая сборка Synex как desktop-приложения: одна загрузка, Python, Node.js и Rust не
нужны.

### Приложение

- Сборки для Windows 10/11 x64 (zip и установщик), Linux x86_64 (tar.gz, Ubuntu 22.04,
  Debian 12 и новее) и macOS 11+ (Apple Silicon и Intel, zip с `Synex.app`). В каждой свой
  `synex_worker`.
- Приложение запускает backend и воркер и открывает UI в своём окне (WebView2 на Windows,
  WebKit на macOS) или в браузере (Linux). Второй запуск открывает уже работающую копию.
  Закрыли окно — всё останавливается.
- Данные пользователя между версиями лежат в одном месте: `%LOCALAPPDATA%\Synex`,
  `~/Library/Application Support/Synex`, `~/.local/share/synex` (ключи, сохранённые
  подключения, история терминала, правила алертов, настройки `synex.env`, `logs/`).
- Память без окна: около 100 МБ (backend и воркер), см. описание выпуска.

### Возможности

- SSH: несколько сессий, зашифрованное хранилище ключей, сохранённые подключения,
  проверка ключа сервера (TOFU, `known_hosts` OpenSSH).
- Терминал: история команд по серверам, дополнение по Tab, Ctrl+C прерывает идущую
  команду, команды до 10 минут, подсказка вместо зависания для программ, которым нужен
  настоящий терминал (vim, top, tmux).
- Мониторинг: CPU, память, диски, сеть и GPU каждого сервера дважды в секунду.
- Алерты: пороги CPU, памяти, дисков, температуры GPU и «сервер не отвечает» для всех
  серверов, с историей и отметкой «увидел».
- Логи выбранного сервера: журнал systemd с фильтрами по юниту, уровню, времени и тексту,
  файлы логов из `/var/log`, всё вживую.
- Файлы: двухпанельный SFTP-менеджер, папки со сверкой, поиск на сервере и на этом
  компьютере.
- Docker: контейнеры, действия, логи и живые логи. Git: статус, история, pull, деплой.
- Плагины: каждый модуль включается и выключается на ходу.

### Известные ограничения

- В терминале пока нет настоящего TTY: полноэкранные программы не работают (нужна
  поддержка PTY в ядре).
- Сборки не подписаны: Windows SmartScreen и macOS Gatekeeper спросят подтверждение при
  первом запуске.
- UI собран под порт 8000: если он занят, задайте другой `PORT` в `synex.env` и пересоберите
  или освободите порт.
